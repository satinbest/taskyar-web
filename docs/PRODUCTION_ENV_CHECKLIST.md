# چک‌لیست امنیت و آماده‌سازی محیط پروداکشن (Production Environment Checklist)
# TaskYar Web 2.0 Release Candidate

پیش از راه‌اندازی و اعلام دسترسی عمومی به سامانه تسک‌یار بر روی سرور یا هاست نهایی، تک‌تک موارد این چک‌لیست را بررسی و تایید نمایید:

---

## ۱. تنظیمات حیاتی فایل `.env`

| متغیر | مقدار مورد انتظار در پروداکشن | وضعیت | علت و اثر امنیتی |
| :--- | :--- | :--- | :--- |
| `APP_ENV` | `production` | [ ] | غیرفعال‌سازی ابزارهای توسعه و مانیتورینگ محلی |
| `APP_DEBUG` | `false` | [ ] | **حیاتی:** جلوگیری از افشای کوئری‌های SQL، متغیرهای محرمانه و Stack Trace به کاربران |
| `APP_KEY` | مقدار ۳۲ بایتی یکتا (`base64:...`) | [ ] | **حیاتی:** رمزنگاری ایمن کوکی‌های سشن و داده‌های محرمانه |
| `APP_URL` | آدرس دقیق دامنه با `https://` | [ ] | جلوگیری از حملات Host Header Injection و آدرس‌دهی دقیق دارایی‌ها |
| `DB_CONNECTION` | `mysql` | [ ] | استفاده از موتور پایگاه داده رابطه‌ای سازمانی با پشتیبانی از تراکنش‌های ACID |
| `DB_PASSWORD` | رمز پیچیده حداقل ۲۰ کاراکتر | [ ] | جلوگیری از حملات Brute Force |
| `SESSION_DRIVER` | `database` یا `file` | [ ] | مدیریت مستقل و منزوی نشست‌ها در پایگاه داده |
| `SESSION_SECURE_COOKIE` | `true` | [ ] | ارسال کوکی‌های سشن صرفاً از کانال رمزنگاری‌شده HTTPS |
| `SESSION_HTTP_ONLY` | `true` | [ ] | جلوگیری از دسترسی اسکریپت‌های کلاینت به کوکی‌های احراز هویت (دفاع در برابر XSS) |
| `SESSION_SAME_SITE` | `lax` یا `strict` | [ ] | محافظت کامل در برابر حملات جعل درخواست میان‌سایتی (CSRF) |
| `LOG_LEVEL` | `warning` یا `error` | [ ] | جلوگیری از اشغال فضای دیسک با لاگ‌های جزئی Debug و حفاظت از اطلاعات کاربران |

## ۲. ایمنی دسترسی به وب و وب‌سرور (Web Server & Directory Security)

- [ ] **عدم دسترسی به فایل `.env` از طریق مرورگر:**
  - با مرورگر به آدرس `https://yourdomain.com/.env` بروید؛ باید خطای **403 Forbidden** یا **404 Not Found** دریافت شود.
- [ ] **عدم دسترسی به پوشه‌های داخلی لاراول:**
  - آدرس‌های `https://yourdomain.com/app/`, `https://yourdomain.com/storage/logs/laravel.log`, `https://yourdomain.com/vendor/` نباید در دسترس باشند.
- [ ] **غیرفعال بودن Directory Listing:**
  - پوشه‌هایی مانند `/icons/` یا `/fonts/` نباید لیست محتویات دایرکتوری را نمایش دهند (`Options -Indexes` در `.htaccess` فعال باشد).
- [ ] **گواهی معتبر SSL/TLS:**
  - فعال‌سازی گواهی معتبر و ریدایرکت خودکار ترافیک HTTP به HTTPS.
- [ ] **هدرهای امنیتی HTTP:**
  - هدرهای `X-Frame-Options: SAMEORIGIN` و `X-Content-Type-Options: nosniff` فعال باشند.

---

## ۳. دارایی‌های ایزوله و فرانت‌اند (Frontend & PWA Isolation)

- [ ] دارایی‌های پروژه توسط `npm run build` کامپایل شده و در `public/build/` قرار دارند.
- [ ] عدم نیاز به اجرای Node/Vite روی سرور میزبان.
- [ ] قلم وزیری‌متن (Vazirmatn) و فایل‌های CSS/JS به صورت محلی لود می‌شوند (صفر وابستگی به CDN خارجی).
- [ ] فایل `manifest.webmanifest` و `sw.js` با کد وضعیت 200 و نوع محتوای معتبر لود می‌شوند.
- [ ] سرویس‌ورکر هیچ‌یک از مسیرهای حساس احراز هویت یا داده‌های خصوصی `/api/*` را کش نمی‌کند.

---

## ۴. سطوح دسترسی فایل‌ها در سیستم‌عامل (Filesystem Permissions)

- [ ] مالکیت کلیه فایل‌ها متعلق به کاربر اختصاصی هاست اشتراکی است.
- [ ] پوشه `storage/framework/views`، `storage/framework/sessions`، `storage/framework/cache` و `storage/logs` دارای دسترسی نوشتن برای PHP هستند (مجوز `755` یا `775`).
- [ ] پوشه `bootstrap/cache` دارای دسترسی نوشتن است (`755` یا `775`).
- [ ] هیچ فایل یا پوشه‌ای در پروژه مجوز ناامن `777` ندارد.

---

## ۵. پایگاه داده و مهاجرت‌ها (Database & Migrations)

- [ ] مایگریشن‌های رسمی فاز ۱ تا ۶ تا آخرین مرحله اجرا شده‌اند (`php artisan migrate --force`).
- [ ] جداول دارای ایندکس‌های ترکیبی برای عملکرد سریع بر روی حجم داده‌های بالا هستند.
- [ ] اکانت پایگاه داده لاراول دسترسی محدودی به پایگاه‌های داده دیگر سرور ندارد.
- [ ] از دیتابیس پشتیبان خام اولیه گرفته شده و در محلی امن نگهداری می‌شود.

---

## ۶. کش و زمان‌بندی (Cache & Scheduler)

- [ ] دستورات بهینه‌سازی اجرا شده‌اند:
  ```bash
  php artisan config:cache
  php artisan route:cache
  php artisan view:cache
  ```
- [ ] کرون‌جاب `php artisan schedule:run` در پنل هاست فعال است.
