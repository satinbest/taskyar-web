# معماری فنی و مهندسی تسک‌یار وب ۲.۰ (System Architecture)

این سند معماری نرم‌افزار، لایه‌بندی داده‌ها، نحوه تعامل کلاینت و سرور، ذخیره‌سازی آفلاین، موتور تکرار و الگوهای طراحی پیاده‌سازی‌شده در **تسک‌یار وب ۲.۰** را شرح می‌دهد.

---

## ۱. نمای کلی سیستم (System Overview)

تسک‌یار وب ۲.۰ یک سامانه تک‌صفحه‌ای (Single Page Application - SPA) با پشتیبانی کامل از قابلیت‌های پیشرو وب (PWA) است که بر پایه معماری ماژولار توسعه یافته است:

```text
┌─────────────────────────────────────────────────────────────┐
│                       رابط کاربری (UI)                      │
│      Vue 3 (Composition API) + Tailwind CSS + وزیرمتن      │
└──────────────────────────────┬──────────────────────────────┘
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
┌───────────────────────┐             ┌───────────────────────┐
│     Pinia Stores      │             │   Service Worker &    │
│  (tasks, auth, theme) │             │  Offline Cache (PWA)  │
└───────────┬───────────┘             └───────────────────────┘
            │
            ├─────────────────────────────────────┐
            ▼                                     ▼
┌───────────────────────┐             ┌───────────────────────┐
│  IndexedDB (Client)   │             │  RESTful API Client   │
│  ذخیره‌سازی محلی آفلاین  │             │   ارتباط با سرور لاراول│
└───────────────────────┘             └───────────┬───────────┘
                                                  │ (JSON over HTTPS)
                                                  ▼
                                      ┌───────────────────────┐
                                      │ Laravel 11/12 Backend │
                                      │    (PHP 8.4 Router)   │
                                      └───────────┬───────────┘
                                                  │
                                                  ▼
                                      ┌───────────────────────┐
                                      │ MariaDB 10.6 (InnoDB) │
                                      │   ایزولاسیون کامل کاربران  │
                                      └───────────────────────┘
```

---

## ۲. لایه بک‌اند (Backend Architecture)

- **فریم‌ورک:** Laravel 11/12 بر بستر PHP 8.4
- **احراز هویت و امنیت جلسات (Authentication):** مبتنی بر Session و کوکی‌های امن استاندارد لاراول با محافظت پیش‌فرض CSRF و ایزولاسیون بر پایه `auth()->id()`.
- **کنترلرها و روت‌ها:** روت‌های RESTful تحت مسیر `/api/*` که کلیه عملیات CRUD بر روی مدل‌های `Task`, `Subtask`, `Category`, `Tag`, `Analytics` و `Backup` را مدیریت می‌کنند.
- **سیاست‌های دسترسی (Policies):** برای تمامی مدل‌ها (نظیر `TaskPolicy`, `SubtaskPolicy`, `CategoryPolicy`) تعریف شده تا دسترسی هر کاربر به وظایف و زیرتسک‌های اختصاصی خودش محدود شود و هیچ کاربری امکان مشاهده یا تغییر داده‌های سایر کاربران را نداشته باشد (Multi-tenant Data Isolation).
- **پایگاه‌داده و انجین ذخیره‌سازی:** تمامی مایگریشن‌ها صریحاً ویژگی `$table->engine = 'InnoDB';` را ست می‌کنند تا از صحت ارتباطات کلید خارجی (Foreign Keys) در هر دو سرور MySQL و MariaDB با انجین پیش‌فرض MyISAM اطمینان حاصل شود.

---

## ۳. لایه فرانت‌اند (Frontend Architecture)

- **محیط کامپوننت‌ها:** Vue 3 با نحو نوین `<script setup>` و Composition API.
- **مدیریت وضعیت سراسری (Pinia Stores):**
  - `stores/tasks.js`: مدیریت داده‌های وظایف، رخدادهای تکرارشونده، فیلترها، زیرتسک‌ها، محاسبات وضعیت و صف همگام‌سازی آفلاین.
  - `stores/auth.js`: مدیریت وضعیت احراز هویت کاربر، اطلاعات پروفایل و مودال لاگین/ثبت‌نام.
  - `stores/theme.js`: مدیریت تم تاریک/روشن و تم‌های رنگی.
- **مدیریت تاریخ و زمان شمسی (`utils/jalali.js`):**
  - تبدیل بدون نقص میان تقویم‌های میلادی و جلالی بدون نیاز به کتابخانه‌های سنگین خارجی.
  - قالب‌بندی اعداد به ارقام فارسی و تولید نماهای تقویم ماه و هفته.

## ۴. موتور تکرار وظایف (Task Recurrence Engine)

موتور تکرار وظایف وظیفه تولید رخدادهای دوره‌ای (Occurrences) بر اساس الگوی تعریف‌شده را بر عهده دارد:
1. **الگوهای تکرار (`recurrence_pattern`):**
   - `daily` (روزانه)، `weekly` (هفتگی بر اساس آرایه روزهای مشخص)، `monthly` (ماهیانه)، `yearly` (سالیانه).
2. **شروط پایان (`recurrence_end_date` یا `recurrence_count`):** پایان در تاریخ مشخص یا پس از تعداد دفعات مشخص.
3. **مدیریت استثنائات (`TaskRecurrenceException`):**
   - جدول `task_recurrence_exceptions` رخدادهایی که توسط کاربر رد (Skip) شده یا مستقل ویرایش (Detach/Edit) شده‌اند را ذخیره می‌کند تا بدون نیاز به تولید بی‌شمار رکورد در دیتابیس، در تقویم نمایش داده نشوند یا به تسک مجزا تبدیل گردند.

---

## ۵. سازوکار کارکرد آفلاین و همگام‌سازی (Offline & IndexedDB)

1. **دیتابیس مرورگر (IndexedDB):** با ورود کاربر، پایگاه‌داده اختصاصی برای شناسه کاربر در IndexedDB باز شده و تمام وظایف ذخیره می‌شوند.
2. **به‌روزرسانی خوش‌بینانه (Optimistic Updates):** هنگام ایجاد، ویرایش یا حذف کار، تغییرات بلافاصله در رابط کاربری و IndexedDB اعمال می‌شوند؛ کاربر حتی در سرعت بسیار پایین اینترنت یا حالت قطع کامل شبکه احساس تأخیر نمی‌کند.
3. **صف جهش‌ها (Mutation Queue):** در صورت قطع ارتباط، درخواست‌ها در صف ذخیره شده و به محض وصل شدن اینترنت، با ارسال به اندپوینت `/api/sync` با سرور همگام می‌شوند.
